# WCU fit for DaVinci Resolve 21.1

September 8, 2026. Capability assessment based on the installed WCU release, repository evidence, and Blackmagic's 21.1 announcement, release notes, and manual. No Resolve task was executed. No Resolve window was present, and the standard `/opt/resolve` installation and matching application launchers were not found in the locations checked. This does not establish that Resolve is absent from every possible location.

**WCU is a promising companion for supervised Resolve workflows. For Studio 21.1, start with native MCP and scripting for supported project operations, then use WCU where visual evidence or UI interaction adds value.** WCU's recent improvements make that second role more practical, but there is no measured Resolve success rate or speedup yet.

The release adds assistant integration alongside UI changes relevant to WCU: editable media-pool list fields with Tab/Enter navigation, inspector presets, marker PDF reports, expanded multicam shortcuts, archive options, and Fusion macro improvements. These provide useful pilot tasks. They are not evidence that the corresponding controls expose accessibility or that WCU already knows their navigation. [Blackmagic announcement](https://www.blackmagicdesign.com/media/release/20260908-03).

The detailed notes confirm a native MCP server and state that advanced scripting now requires Studio. New APIs cover such operations as keyboard presets, render presets, transcription retrieval, multicam creation, transitions, inspector properties, audio normalization, and project-setting presets. Those are reasons to test native operations before implementing equivalent mouse sequences. [Studio 21.1 release notes](https://www.blackmagicdesign.com/support/content/readme/baf7c071c0524fbf8ccc961925c9f443).

The manual's “Using DaVinci Resolve with AI Assistants” section, page 4318, describes Studio integration and gives examples involving timeline analysis, clip renaming, markers, LUTs, settings, reframing, and rendering. It documents `File > Setup AI Assistants`. The section establishes intended workflows, not a complete MCP tool schema or an assurance that every requested operation is supported. Its example codec requests are also not guarantees of codec availability on Linux. [Resolve 21.1 manual, page 4318](https://documents.blackmagicdesign.com/UserManuals/DaVinci_Resolve_21.1_Reference_Manual.pdf#page=4318).

| Workflow | Expected WCU usefulness | Recommended execution and evidence |
|---|---|---|
| Media organization and metadata | Moderate as a UI fallback; a good WCU pilot | Prefer native reads/writes for bulk operations. Test a small list-view edit using the new keyboard navigation, then verify exact clip identities and field values. Sorting and filtering must not silently change the destination row. |
| Settings, inspector presets, archive options, and marker PDF export | Promising for controls missing from native tools | Inspect the real dialog, establish selection and focus, execute a short predictable portion, and verify saved settings or exported files. Confirm actual API gaps before calling these UI-only tasks. |
| Batch rendering and repetitive timeline changes | Limited incremental value for issuing supported commands; useful visual fallback | Native tools should be tested for submission and state readback. WCU can inspect visible errors and dialogs. Check job identity, completion state, and the resulting media; an idle progress display or a successful click is insufficient. |
| Reframing, titles, and selected-frame review | Promising for visible composition checks | Apply exact changes through native tools where possible. Pause at known timecodes and use WCU to inspect framing, clipping, text, and overlays. Sampled frames do not establish quality throughout the video. |
| Multicam editing and trimming | Conditional for discrete, paused operations; poor for live switching | Verify the active panel, selected clip, keymap, playhead position, and resulting edit. WCU does not provide frame-scheduled input or a continuous audiovisual feedback loop. More shortcut targets do not solve that timing problem. |
| Fusion templates and effects | Moderate for choosing templates and entering known parameters; uncertain for complex graph construction | Prefer scripts/macros when available. WCU can inspect the visible graph and dialogs, but repeated coordinate decisions remain expensive and layout-sensitive. |
| Color grading and Fairlight finishing | Useful for setup, exact parameter entry, and coarse visual inspection | WCU supplies screenshots and input, not calibrated HDR monitoring or audio capture. It cannot independently certify color accuracy, loudness, sync, or the creative quality of a mix. |
| Work spanning Resolve and other apps | Promising where no structured connector exists | WCU can bridge visible file dialogs, notes, and other native apps. Use ordinary file/API operations for structured transfers when available. Shared desktop focus and clipboard state remain part of the workflow. |

The recent WCU changes have concrete value here:

- Guarded batches can combine verified keyboard navigation and text entry. Per-segment checks and explicit window transitions help with project managers, dialogs, and inter-app handoffs. The execution ledger distinguishes submitted input from verified outcomes and supports reconciliation after partial execution.
- Scoped accessibility and text readback can validate fields and readiness **if Resolve exposes usable evidence**. Window focus alone does not establish that the intended control is ready. Where accessibility is absent, fresh screenshots and independent project/output checks are still necessary.
- Target and region screenshots can reduce irrelevant pixels and improve inspection of dense panels. A maximized Resolve window is much larger than the small benchmark fixtures, so their image-size savings cannot be assumed here.
- Context retrieval and validated recipes offer a place for Resolve knowledge, but there is no shipped Resolve catalog. A live exact-app context query returned `no_result`. A versioned Resolve catalog and verified user keyboard preset would be useful additions; retrieval cannot manufacture missing coverage.

These are grounded in the [current WCU contract](../skills/wayland-computer-use/references/execution-and-context.md), [environment catalog coverage](../skills/wayland-computer-use/references/environment-context.md), and [September 8 implementation results](2026-09-08-wcu-braid-implementation-results.md).

The existing benchmark passed 27 deterministic task artifacts. Holding monitor capture constant, batching reduced median form time by 37% and browser-to-note transfer time by 47%; it offered effectively no reduction for the single-input canvas task. The trials exclude model inference and approval time. The two model-driven form smoke tasks also passed, with rejected requests recorded separately. These support testing repetitive Resolve controls; they do not establish general agent performance in Resolve. The natural asynchronous focus test still delivered input to a decoy window, so the revised guard is not atomic isolation.

Resolve presents additional limits worth measuring directly. Playback, scopes, meters, and animated panels may invalidate WCU's pixel guards. A stopped or stable crop is only evidence of pixels, not a finished render. WCU currently lacks semantic activation, modified-drag parameters, and asynchronous input. Coordinate actions can only begin a `run_steps` batch, and drag is a separate tool, so arbitrary sequences of clicks or graph gestures still need repeated observations. There is no audio observation tool. See the [current README](../README.md) and [input tool definitions](../scripts/server.py).

Resolve's Linux release is available, but its listed Linux system requirements name Rocky Linux 8.6; that does not certify this Omarchy/Hyprland session. Capture, typing, dialogs, accessibility, GPU behavior, and any XWayland interaction need a live smoke test. For the free edition, WCU's relative value may be greater because it can operate available GUI functions, but it does not unlock Studio functionality. The edition distinction should be retained in any benchmark. [Official download catalog](https://www.blackmagicdesign.com/api/support/us/downloads.json), [release requirements](https://www.blackmagicdesign.com/support/content/readme/baf7c071c0524fbf8ccc961925c9f443).

For the next application evaluation, use a disposable project with synthetic clips and compare **WCU alone, native MCP alone, and a combined route** on the same tasks:

1. Establish compatibility and evidence coverage across the media list, inspector, a file dialog, timeline, Fusion graph, and render queue. Inspect active keyboard presets and desktop shortcut interception. Test paused and playing states separately.
2. Edit metadata on ten identified clips; apply and verify an inspector preset; export a marker PDF and a used-media archive; reframe a short timeline and inspect specified frames; render two short deliverables.
3. Reset the project between routes, alternate route order, and repeat at least five times with held-out names and values. Mark unsupported operations as coverage gaps. Use equivalent final verification for every route.
4. Measure end-to-end elapsed time including model and approval time, correct final artifacts, human interventions, tool calls, guard rejections, outcome timeouts, and recovery effort. For renders, inspect file metadata and decodability. For timelines, inspect clip identities, timecodes, and requested parameters through structured readback where available.

Prioritize the Resolve compatibility/evidence probe and a small validated shortcut catalog before expanding WCU itself. A combined route earns its place if it completes useful tasks beyond native coverage or catches visible defects at acceptable cost. Any claim that it saves time should follow the paired Resolve measurements.
